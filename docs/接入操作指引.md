# 平台接入操作指引（照做即可，每步都有验证方式）

> 目标：把飞书、钉钉（可选 Telegram）的凭证拿到手，并**用一条命令证明它真的通了**。
> 全程不需要公网 IP、不需要域名、不需要内网穿透——三个平台都是出站长连接。

---

## 0. 前置：装客户端

```powershell
winget install ByteDance.Feishu -e --accept-package-agreements --accept-source-agreements
winget install Alibaba.DingTalk.Mainland -e --accept-package-agreements --accept-source-agreements
```

客户端只用来「当用户发消息」，开发本身不依赖它。

## 1. 飞书（预计 15 分钟）

### 1.1 建一个自己的「企业」
个人版账号**不能**创建自建应用，必须先有企业（免费、无需营业执照、无需认证）。

- 飞书 PC 端 → 左上角头像 → **创建或加入企业/团队** → 创建团队，名字随意（例：`XX 实验室`）
- 创建后**切换到该团队**（头像处切换组织），否则开放平台会看不到应用入口

### 1.2 创建应用
1. 浏览器打开 <https://open.feishu.cn/app>
2. **创建企业自建应用** → 填名称（例：`统一收件箱`）、描述、随便选个图标
3. 进入应用 → **凭证与基础信息** → 复制 **App ID** 和 **App Secret**
   → 粘贴到 `.env` 的 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`

### 1.3 开机器人能力
**添加应用能力** → **机器人** → 添加

### 1.4 开权限
**权限管理** → 搜索并开通（开通后需发布版本才生效）：

| 权限 | 用途 | 是否踩过坑 |
| --- | --- | --- |
| `im:message.p2p_msg:readonly` | **读取用户发给机器人的单聊消息** | ⚠️ **必须单独开**，只开 `im:message` 收不到单聊消息事件 |
| `im:message` | 获取与发送单聊、群组消息 | 发消息用 |
| `im:resource` | 上传/下载文件、图片 | 发文件用 |
| `im:chat:readonly` | 列出机器人所在群（可选，仅排障用） | — |
| `contact:user.base:readonly` | 读发件人基本信息（可选） | — |

> **血泪教训（本项目实测）**：只开 `im:message` 时，后台「事件与回调」页面会显示「请开通以下任一权限」，
> 长连接能连上（`connected to wss://msg-frontier.feishu.cn/ws/v2`）但**一条事件都收不到**，
> 日志检索也是「暂无数据」。补开 `im:message.p2p_msg:readonly` 后**立刻**就能收到。
> 飞书这类免审权限是即时生效的，不需要重新发版本。

### 1.5 事件订阅（关键，别选错）
**事件与回调** → **订阅方式** 选 **「长连接」**（不是 Webhook！）
→ **添加事件** → 搜索 `im.message.receive_v1`（接收消息）→ 添加

添加后表格里应显示：订阅类型「**应用身份**」、所需权限「已满足」。
若「所需权限」仍是红色「请开通以下任一权限」，回到 1.4 补权限。

### 1.6 发布
**版本管理与发布** → 创建版本（版本号 `1.0.0`，可用范围选全体成员）→ 申请发布
→ 因为你是管理员，**自己审核通过**，状态变成「已发布」才生效

### 1.7 验证（到这里才算真通）

```powershell
cd "C:\Users\75090\Desktop\DEEP SEEK\unified-inbox\backend"
.\.venv\Scripts\python.exe scripts\probe.py feishu --listen 60
```

看到 `请现在打开飞书…私聊发一句` 时：
飞书里点顶部搜索框 → 输入应用名 `统一收件箱` → 进入单聊 → 发「测试」

**通过标志**：脚本打印 `✅ 收到事件：{... "text": "测试"}`。
这一步的日志文件已自动存到 `docs/证据/feishu-probe-*.log`，直接当初赛连通性证据提交。

## 2. 钉钉（预计 12 分钟）

### 2.1 建团队
钉钉 PC 端 → 创建团队（免费）。

### 2.2 创建应用
1. <https://open-dev.dingtalk.com> → **应用开发** → **企业内部应用** → 创建应用
2. **凭证与基础信息** → 复制 **Client ID（原 AppKey）** 和 **Client Secret（原 AppSecret）**
   → 粘贴到 `.env` 的 `DINGTALK_CLIENT_ID` / `DINGTALK_CLIENT_SECRET`
3. 记下 **RobotCode**（机器人编码）→ 填 `DINGTALK_ROBOT_CODE`

### 2.3 开机器人 + 选 Stream 模式（关键）
**应用能力** → **机器人** → 配置
→ **消息接收模式** 选 **「Stream 模式」**（不是 HTTP 回调！）
→ 消息接收地址不用填

### 2.4 权限与发布
**权限管理** → 开通「企业内机器人发送消息」相关权限
→ **版本管理与发布** → 发布（钉钉必须发布后才生效）

### 2.5 验证

```powershell
.\.venv\Scripts\python.exe scripts\probe.py dingtalk --listen 60
```

期间在钉钉搜机器人名 → 单聊发一句。
**通过标志**：`✅ 收到钉钉消息：{...}`，日志存 `docs/证据/dingtalk-probe-*.log`。

## 3. Telegram（预计 3 分钟）

1. Telegram 里搜 **@BotFather** → 发 `/newbot` → 起名 → 拿到 token
2. 填入 `.env` 的 `TELEGRAM_BOT_TOKEN`

4. 在 Telegram 里给对方机器人发一句话，再跑一次 `--listen 60` 看是否收到。

## 5. 常见卡点（按出现频率排序）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 飞书开放平台看不到「创建应用」按钮 | 当前租户还是个人版 | 先建团队并切换到该团队 |
| 飞书 `取 tenant_access_token 失败` | App ID/Secret 抄错，或应用被停用 | 回「凭证与基础信息」重抄，注意首尾空格 |
| 飞书发消息失败 `权限不足` | 权限开了但没发版本 | 创建版本 → 申请发布 → 审核通过 |
| 飞书长连接连上但收不到事件 | ① 没开 `im:message.p2p_msg:readonly`（最常见）；② 订阅方式选成了 Webhook；③ 没加 `im.message.receive_v1` | ① 权限管理补开该权限（即时生效）；② 事件与回调改成「长连接」；③ 补事件 |
| 飞书里搜不到机器人 | 应用没发布，或搜索的账号不在同一企业 | 发布应用；确认账号在同一团队 |
| 钉钉 Stream 连不上 | 消息接收模式还是 HTTP 回调 | 改为 Stream 模式并重新发布 |
| 钉钉发出消息又收到自己发出的 | 机器人会收到自己消息 | 代码已用 `senderStaffId == chatbotUserId` 过滤，属正常 |
| 采集不到群消息 | 飞书机器人在群里需 @ 才触发（默认） | 演示用单聊最稳；群聊请 @机器人 |
| Windows 控制台输出乱码 | 代码页是 GBK | 先执行 `chcp 65001`，或直接用 Windows Terminal |

## 6. 凭证安全（架构评分红线）

- 所有密钥只从 `.env` 读，代码里零硬编码（`backend/app/config.py` 是唯一入口）
- `.env` 已在 `.gitignore` 中，不会进仓库
- 提交前自查：`git grep -nE "(app_secret|client_secret|bot_token)\s*=\s*\"[A-Za-z0-9]"` 应无结果
- 演示录屏时把 `.env` 面板打码，或先 `Ctrl+H` 替换成 `***`
