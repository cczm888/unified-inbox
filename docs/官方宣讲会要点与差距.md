# 官方宣讲会要点与我们的差距

> 来源：`https://meeting.tencent.com/rs/Nb4Mpj8q10`（腾讯会议 AI 纪要，发言人：杨耿）
> 抓取时间：2026-11-20
> 全文见 `_ego/feishu-setup-20261102-1750/meeting-notes.txt`

这份纪要有**五处**和此前的理解不一致，其中两处会直接改变工作量估算。先列结论，再说细节。

---

## 一、必须立刻知道的五条

### 1. 初赛推迟到 11 月 22 日

原计划 11/20，现在多两天。多出的时间**不应用于加功能**，应用于把五类文档补齐
（见第三节，我们目前一份都不符合格式）。

### 2. RPA 是官方认可的接入方式

原文：

> **RPA 自动化补充方案**：若平台未开放 API 或申请困难，可使用 Windows 下的
> Power Automate 等桌面机器人，模拟鼠标键盘操作拷贝消息并发送。
>
> 跨平台消息互通：对接主流平台 API 实现文本消息发送 / **无 API 时采用 RPA 自动化模拟操作**

**这修正了我此前的一个保守判断**——我曾把「飞书网页版 DOM 采集器」标注为
「不计入赛题要求的平台数，只是补充通道」。按官方口径，RPA 是被明确允许的替代路径，
采集器可以作为**合法接入方式之一**计入。

但注意措辞是「**模拟鼠标键盘操作拷贝消息并发送**」——**能发**才算数。我们目前的
采集器只读不写，需要补 RPA 发送才能完整对上这句话。

### 3. 闭环要求比我们做的更"产品化"

原文要求闭环包含：

> 系统需包含**用户注册、配置平台、查看朋友清单或新消息列表、选择联系人发送消息
> 以及自动或人工回复**等完整闭环逻辑。

对照我们现状：

| 环节 | 我们的状态 |
| --- | --- |
| 用户注册 | ❌ 只有单一访问口令，没有账号体系 |
| 配置平台 | ✅ 抽屉里填凭证即接入，可停用/启用 |
| 查看朋友清单或新消息列表 | ⚠️ 有会话列表，但没有"朋友/联系人"概念 |
| 选择联系人发送消息 | ⚠️ 只能回复已有会话，不能主动选人发起 |
| 自动或人工回复 | ✅ 人工回复 + AI 草稿；无自动回复规则 |

「用户注册」和「选择联系人主动发消息」是我们目前**明确缺的两块**。

### 4. 目标场景是「人与人」，不是「人与机器人」

原文：

> 实现人与人消息互通：需对接至少两个主流平台……通过官方开放API实现**平台内个体
> 用户之间**的文本消息发送。

我们现在的链路是「用户 ↔ 机器人」。严格说，用户 A 发给机器人、机器人再发给用户 B，
中间经过了机器人，不是纯人与人的直连。

**这正是 RPA 方案的价值**：以用户身份操作客户端，就能给任意联系人发消息，
天然是"人与人"。所以第 2 条和第 4 条是同一个答案。

### 5. 严禁直接提交 AI 生成结果，用 AI 必须附对话过程链接

原文：

> **严禁直接提交 AI 生成结果**
> 使用AI辅助设计必须附上对话过程链接，以证明优化和思考过程。
> 当前提交的部分作品像交作业，缺乏详细的理解和过程分析。

这条对我们是**加分项而非风险**——整个项目的过程都在这个会话里，可以整理成
「AI 协作过程记录」附在文档里。但要真的整理，不能只贴一句"使用了 AI"。

## 二、初赛要交的五类文档（我们目前一份都不合规）

| 文档模块 | 官方要求 | 我们现有 | 差距 |
| --- | --- | --- | --- |
| **需求分析** | 需求理解、功能清单、核心业务流程图 | `初赛设计文档.md` 有业务闭环图与用户旅程 | 缺独立的「需求理解」章节与完整功能清单 |
| **原型设计** | 软件界面清单 + **与实际功能一致的**界面设计图 | 只有运行时截图 | 需界面清单 + 逐屏设计图（截图可，但要编号并配说明） |
| **数据库设计** | 数据表清单、数据表内容、**建表 SQL** | `backend/sql/001_init.sql` 已同步 | ✅ 基本达标，只需整理成章节 |
| **接口设计** | 接口清单及**路由、请求方式**等详情 | `docs/审查材料索引.md` 有接口表 | 需扩成「方法 + 路径 + 参数 + 响应 + 错误码」 |
| **初步验证** | 技术栈及难点、**测试截图及结果解释** | `docs/证据/` 有日志，`初赛设计文档.md` §9 有证据表 | 需把日志变成「截图 + 结果解释」 |

### 排版规范（评审会直接扣分）

- 首页**仅含**项目及队伍信息（不能有目录、不能有正文）
- 第二页为**自动目录**（Word 域生成，不是手打）
- 正文页码从 **1** 开始（封面和目录不计页码）
- **1.5 倍行距**
- 标题格式「一、1.1、1.1.1」，**最多三级**
- 图表**顶格居中**，序号与名称按规范
- **每个图表需附 100–200 字说明**（这条最容易漏）

## 四、一句话总结

我们做的技术深度是够的（三平台、闭环、Outbox、26 个测试、真机证据），
但**交付形态和题目要求有结构性偏差**：

- 题目要的是**一份讲清楚设计过程的文档**，我们交的是**一个能跑的系统**；
- 题目要的五类是「需求分析 / 原型 / 数据库 / 接口 / 初步验证」，
  我们写的是「设计文档 + 可行性分析」；
- 题目明确说 RPA 可以，我们反而自我设限把它降级成了"补充通道"。

接下来两天的主战场是**文档**，不是代码。代码只需补两块（注册、主动发消息）。
