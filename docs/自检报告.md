### 第 2 + 4 条：RPA 发送是怎么通的

一句话：**网页版里点会话、打字、回车**，走的是浏览器，不是 API。

```
网页点「新消息」→ POST /inbox/send {platform:"feishu_web", target:"用户472908"}
  → outbox.status = 'rpa'（等人来领，不是 'sending'）
  → scripts/rpa-send.mjs 取任务
  → 打开飞书网页版 → 点目标会话 → 验证头部标题 → 输入框打字 → 回车
  → POST /rpa/ack {ok:true} → outbox.status = 'sent'
```

实测结果（截图 `_ego/.../rpa-07-ok.png`）：`{"done":true,"sent":1,"report":[{"id":18,"ok":true,"chat":"用户472908","chars":37}]}`，飞书「用户472908」会话里出现该消息，左栏预览同步。

**「用户472908」是真人**，这条消息是"陈zm 发给 用户472908"，不是机器人中转 —— 第 4 条成立。

### 这里踩了一个真事故，必须写下来

第一版跑完返回 `sent:1, ok:true`，数据库也是 `status=sent`，**但消息进了「豆包工作」不是「用户472908」**。

原因：网页版默认停在一个会话上，点左栏行如果没点准，页面不报错也不提示；随后找到的输入框是**当前**会话的，打字回车全成功，只是发给了错的人。

修法：点完回读右侧聊天头部标题，和目标名比对，三次对不上就失败放弃（宁可不发也不发错人）。commit `ef5febf`。

> 教训：RPA 每一步都"看起来成功了"，所以每一步都要独立校验 —— 点会话验标题、打字验字数、发送验消息出现在列表里。

### 第 4 条为什么之前判定"不达标"

不是技术问题，是平台权限：

- 飞书自建应用的用户身份**读不到消息**（`im:message.*:get_as_user` 不在权限目录里，实测 400 code=230027）；
- 钉钉要"会话内容存档"（企业付费能力）；
- 所以"以用户身份收发消息"只有 RPA 一条路。

这也是为什么第 2 条和第 4 条是同一个答案：RPA 做完整了，第 4 条才成立。
