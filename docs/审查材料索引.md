## 3. 数据库结构

### 3.1 建表 SQL

`backend/sql/001_init.sql` —— 7 张表的完整 DDL（PostgreSQL 方言），可直接执行。

### 3.2 模型定义

`backend/app/models.py` —— 与 SQL 一一对应，含 SQLite/PostgreSQL 双方言适配：

```python
JSON_TYPE  = JSON().with_variant(JSONB(), "postgresql")
PK_BIGINT  = BigInteger().with_variant(Integer, "sqlite")   # SQLite 只有 INTEGER PK 才自增
UTCDateTime(TypeDecorator)                                   # 统一时区，避免 naive datetime
```

### 3.3 表清单

| 表 | 作用 | 关键字段 |
|---|---|---|
| `message` | 统一消息表（收发都在这） | `platform` + `platform_msg_id` 唯一约束；`direction` in/out；`status` 4 态；`priority` 3 级；`read_at`；`attachments` JSONB；`raw` 原始报文 |
| `outbox` | 出站队列 | `status` queued→sending→sent/failed/dead；`attempts`；`next_retry_at`；`result_msg_id` |
| `todo` | 待办 | `source_message_id`；`status` 4 态；`platform_todo_id` |
| `platform_account` | 平台凭证（加密） | `app_secret_enc`（Fernet 密文）；`label`；`extra`；`status` active/disabled/error |
| `user_account` | OAuth 用户身份 | `access_token_enc` / `refresh_token_enc`；`token_expires_at` |
| `event_log` | 原始事件留痕 | `raw`；用于排查"平台到底推没推" |
| `feedback` | 处理反馈 | `kind`（category/priority/reply_template/todo_status）；`old_value` → `new_value` |

### 3.4 关键数据流

```
平台事件 → event_log（留痕）
        → adapters/{platform}.py::to_unified()  → UnifiedMessage
        → services/inbound.py::handle_inbound()
            → message 表（on_conflict_do_nothing 去重）
            → SSE 推前端

用户回复 → api/inbox.py::reply  → outbox（queued）
        → services/outbox.py::worker_loop()
            → ratelimit（Redis 令牌桶）
            → adapters::send_text()  → 平台 API
            → outbox.sent + result_msg_id
            → message 表补一条 direction=out
```

### 3.5 实测数据量

```
message    20 条（飞书 19 + 邮箱 1）
outbox      9 条（全部 sent）
todo        1 条
feedback   25 条
event_log   6 条
```
